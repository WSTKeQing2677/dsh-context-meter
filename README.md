# dsh-context-meter

给 **DSH（DeepSeek Harness）** 用的小插件：在输入框里常驻一行字（视觉上在输入框中间偏左），告诉你**离自动压缩还有多远、离硬上限还有多远**。

```
吃紧 · 距压缩 18万 · 距上限 50万
```

它落在输入框内部那行控件里（宿主文档管它叫 composer 工具行），视觉位置在输入框中间偏左；不占消息区，也不浮在输入框外面。

不用点开、不用问，扫一眼就知道这段对话还能撑多久。

## 它显示什么

五档，全部以 DSH 自己的**自动压缩阈值**为基准：

| 首字 | 含义 | 悬停那一句 |
|---|---|---|
| 宽裕 | 还早 | 还早着呢，随便聊。 |
| 过半 | 一半没了 | 一半没了，剩下的够用一阵。 |
| 吃紧 | 有点挤 | 有点挤了，说重点吧。 |
| 该走了 | 该开新会话了 | 该到分别的时候了——开个新会话，我还认得你。 |
| 最后一程 | 快撞墙了 | 再不走，前面说过的话我就要忘了。 |

两个数字都是**还剩多少**：

- **距压缩**：再花这么多 token 就触发自动压缩。压缩后前面的对话会变成摘要。
- **距上限**：再花这么多就撞上下文硬上限。

## 数据从哪来（不是估算）

- **已用**：Session 自己的 `contextPressure` 投影（`projectedTokens ?? pressureTokens`）——和 DSH 输入框里那个内置用量环读的是同一个值。
- **窗口**：同一投影的 `contextWindow`。
- **输出预留**：最新 `request/header` 事件的 `maxTokens`。
- **阈值**：`floor(min(W × 0.8, W − maxTokens − 65536))`，与 `compaction-basic` 的 `thresholdRatio` / `headroom` 一致；读不到 `maxTokens` 时退回 `floor(W × 0.8)`，也是它自己的降级行为。

读不到可用的用量或窗口时**整行不渲染**，绝不显示一个猜出来的数。

## 为什么不显示百分比

DSH 宿主自己已经显示了一个占窗口的百分比（比如 54%）。这里再叠一个占**阈值**的百分比（比如 78%），两个数并排会被当成 bug。所以只给「还剩多少」。

## 安装

```bash
git clone https://github.com/<your-github-user>/dsh-context-meter.git
```

然后在 DSH 会话里对 AI 说：

```
用 plugin_manager 安装 <克隆下来的绝对路径>
```

装完**按 F5 刷新页面**——这是客户端插件，不刷新看不到。

> 按路径安装只是在 profile 里建一个指向该目录的链接，**别删、别移动那个目录**，否则插件加载不了。

## 关闭

对 AI 说「关掉上下文余量」，或在「设置 → 插件」里找到 `context-meter` 禁用。关掉只是不显示这行字，不影响任何对话行为。

## 兼容性

- 只在 **DSH `0.2.1-rc.5` + Windows + Web UI** 上验证过。
- 依赖两个内部接口：`conversation.input.left` 插槽、`contextPressure` 投影。版本一变可能失效——它是纯 UI 插件，失效的最坏结果是**这行字不显示**，不影响聊天。
- 阈值公式用宿主给的窗口和 `maxTokens` 实时计算，换模型、改输出上限会自动跟着变。

## 已知行为

- 新会话还没有任何用量时不显示。
- 正在思考/执行时，宿主可能暂时隐藏输入框里那一行控件，这行字会跟着消失一会儿。
- 不显示百分比（见上）。
